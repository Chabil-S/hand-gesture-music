# ระบบควบคุมเพลงด้วยการรู้จำท่าทางมือ

กำหนดส่ง: 8 ตุลาคม 2026 — นำเสนอและเดโมประมาณ 5 นาที

พื้นที่งาน: แชทนี้ แยกจากโปรเจกต์ PM2.5 ไม่มีการแก้หรือย้ายไฟล์ที่ D:\PM2.5

## ขอบเขต

- เล่น/พัก เพลงถัดไป เพลงก่อนหน้า และกลุ่มไม่สั่งงาน
- เป็นท่ามือที่กำหนดเอง ไม่ใช่ระบบแปลภาษามือ
- ใช้ตัวตรวจตำแหน่งมือเป็นตัวสกัดข้อมูล แล้วฝึกโมเดลจำแนกด้วยข้อมูลท่ามือของผู้ใช้เอง
- ชุดท่าที่เสนอในหน้ากล้อง: กำมือ = เล่น/พัก, ชูสองนิ้ว = ถัดไป, ชูนิ้วโป้ง = ก่อนหน้า; neutral = แบมือ/ชูนิ้วชี้/มือผ่อนคลาย ยังต้องทดลองความสะดวกของผู้ใช้ และยังไม่เลือกอัลกอริทึมจำแนกสุดท้าย
- ต้องเห็นท่าต่อเนื่องช่วงสั้นก่อนส่งคำสั่ง และต้องปล่อยท่าก่อนสั่งครั้งถัดไป
- ไม่พบมือหรือข้อมูลไม่น่าเชื่อถือ: ไม่สั่งงาน
- ใช้คำสั่งในเครื่องก่อน ไม่ต้องเชื่อมบริการคลาวด์หรืออ่าน credential ของ Apple

## จุดตัดสินใจแรก: ควบคุมเครื่องเล่นได้จริง

สถานะล่าสุด 4 ตุลาคม: ผ่านการเชื่อมต่อด้วย Windows media session API แล้ว เล่น/พักและถัดไปทำงานขณะหน้าทดสอบอยู่ด้านหน้า ส่วนก่อนหน้าปรับให้ตรวจกรณีย้อนต้นเพลงก่อนกลับเพลงเดิมและทดสอบสำเร็จขณะหน้าแชทอยู่ด้านหน้า รายละเอียดใน CONNECTION_TEST_TH.md ยังต้องทดสอบกับหน้ากล้องจริงและประเมินจำนวนรอบมากขึ้น

ตรวจแอปและทดสอบเล่น/พัก ถัดไป ก่อนหน้า ก่อนสร้างระบบกล้องเต็มรูปแบบ ต้องแยกผลเมื่อ Apple Music อยู่ด้านหน้ากับเมื่อหน้าต่างเดโมอยู่ด้านหน้า ไม่สรุปว่าใช้เบื้องหลังได้จากคู่มือหรือจากการทดสอบด้านหน้า

หากส่งคำสั่งเบื้องหลังไม่ได้ ให้ทดลองวิธีเรียกแอปมารับคีย์แล้วคืนหน้าต่างเดโม โดยรายงานการสลับหน้าต่างเป็นข้อจำกัด และทดสอบก่อนใช้จริง

## ข้อมูลและการฝึกโมเดล

หน้ากล้องเก็บข้อมูลพร้อมแล้ว ดู COLLECTION_GUIDE_TH.md เก็บ 5 รอบ (train 3, validation 1, test 1) รอบละ 4 กลุ่ม ช่วงละ 12 วินาที เก็บเฉพาะพิกัดในเครื่อง ผู้ใช้เป็นผู้กดบันทึกและทำท่าตามป้ายกำกับ ยังไม่ได้เก็บข้อมูลผู้ใช้หรือฝึกโมเดลในรอบเตรียม

อัปเดตหลังเก็บ: มือขวาครบ 20 ช่วง รวม 1,586 ตัวอย่าง ผ่านการตรวจรูปแบบ จำนวน แฮช และการแยกรอบ ผู้ใช้ยืนยันว่าขวาตลอด แต่ตัวตรวจส่ง Left จึงบันทึกข้างจริงแยกจากข้อมูลเดิม เตรียมเก็บมือซ้ายเพิ่มอีก 5 รอบก่อนฝึกโมเดลที่ใช้ทั้งสองข้าง ยังไม่ได้ประเมินความแม่นยำ

อัปเดตหลังมือซ้าย: ครบอีก 20 ช่วง 1,574 ตัวอย่าง รวมสองข้าง 3,160 ตัวอย่าง ตรวจข้อมูลผ่านและฝึกแล้ว เลือก Logistic Regression C=1 จาก validation; test ถูก 634/634 เฟรม (ขวา 322, ซ้าย 312) ผลนี้จำกัดผู้ใช้และรอบที่เก็บ ไม่ใช่อัตราสั่งเพลงจริง ระบบกล้องสดพร้อมโหมดดูผล/เริ่มควบคุม ยืนยัน 0.6 วินาที ปล่อย 0.35 วินาที และมีบันทึกคำสั่ง ต้องทดลองการสั่งงานจริงแยก ดู LIVE_GUIDE_TH.md และ models/20261004_171415/MODEL_REPORT_TH.md

หลังผู้ใช้ลองจริง: พบสามนิ้วโป้ง+ชี้+กลางถูกอ่านเป็น next และคำสั่งที่ทำระหว่างตรวจเพลงหายไป ปรับ runtime ให้ติดตามมือสั่งงานเมื่อเห็นสองมือ รับท่าและการปล่อยต่อเนื่องระหว่างรอ ส่งคำสั่งเป็นคิว และตรวจผลจนพบสถานะเปลี่ยนแทนรอคงที่ 3 วินาที ทดสอบ API toggle ใหม่สองครั้งใช้ 0.125 วินาทีต่อครั้ง ยังต้องลองกล้องสดรุ่นนี้ ตัวกรองนิ้วโป้งทำให้ท่า V จริงถูกตัด จึงปิดไว้และเตรียมเก็บสามนิ้วเป็น neutral เพิ่ม 3 รอบต่อข้าง ปัญหาสามนิ้วยังไม่ถือว่าแก้จนเก็บ ฝึก และทดสอบข้อมูลใหม่ ดู LIVE_FIXES_TH.md

1. เลือกท่าที่ทำง่ายและต่างกันชัดเจน 3 ท่า พร้อมตัวอย่างมือพัก/ท่าอื่นในกลุ่มไม่สั่งงาน
2. เก็บหลายรอบการถ่าย เปลี่ยนระยะ มุมมือและแสงเล็กน้อย เก็บรหัสรอบกับทุกตัวอย่าง
3. แบ่ง train/validation/test ตามรอบการถ่ายทั้งรอบ ห้ามสุ่มเฟรมติดกันข้ามชุด หากมีหลายคนและต้องการอ้างว่าใช้ข้ามคนได้ ต้องแยกตามคนด้วย
4. เลือกโมเดลและค่าการยืนยันท่าจาก validation เท่านั้น เก็บ test ไว้ประเมินท้ายงาน
5. ประเมินการจำแนกด้วย confusion matrix และ precision/recall รายกลุ่ม แยกจากการทดสอบคำสั่งจริง

ตำแหน่งมือเป็นเพียงข้อมูลเข้า ส่วนโมเดลจำแนกที่ฝึกจากตัวอย่างของผู้ใช้เป็นส่วนการเรียนรู้ของงานนี้ ไม่อ้างว่าฝึกตัวตรวจมือขึ้นใหม่

## การประเมินคำสั่งจริง

บันทึกคำสั่งที่ตั้งใจ คำสั่งที่ระบบส่ง ผลในเครื่องเล่น ระยะเวลาตอบสนอง คำสั่งผิด และคำสั่งซ้ำ ทดสอบค้างท่า ปล่อยท่า ไม่เห็นมือ และทำท่าที่ไม่กำหนด ระบุจำนวนครั้งและสภาพทดสอบก่อนรายงานอัตราสำเร็จ
