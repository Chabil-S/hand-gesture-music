# บันทึกทดสอบการควบคุมเพลง

วันที่ตรวจ: 4 ตุลาคม 2026

## ผลรอบยืนยัน: 4 ตุลาคม 2026 เวลา 16:24–16:28 (ไทย)

เลือกใช้ Windows GlobalSystemMediaTransportControlsSession API เป็นช่องทางหลัก ค้นหาเซสชันที่เป็น Apple Music โดยเฉพาะ ไม่ส่งคีย์ไปทุกแอป และไม่อ่าน credential

| การทดลอง | หลักฐานก่อน → หลัง | ผล |
|---|---|---|
| เล่นเมื่อ Apple Music อยู่ด้านหน้า | PAUSED → PLAYING และเวลา 61 → 63 วินาที | ผ่าน 1 ครั้ง |
| พักเมื่อหน้าทดสอบอยู่ด้านหน้า | PLAYING → PAUSED เวลาอยู่ที่ 150 วินาที | ผ่าน 1 ครั้ง |
| เล่นต่อเมื่อหน้าทดสอบอยู่ด้านหน้า | PAUSED → PLAYING เวลา 150 → 153 วินาที | ผ่าน 1 ครั้ง |
| ถัดไปเมื่อหน้าทดสอบอยู่ด้านหน้า | Summertime → ด้วยใจยินดี (Willingly) | ผ่าน 1 ครั้ง |
| ก่อนหน้าแบบคำสั่งดิบ | ด้วยใจยินดี ที่ 15 วินาที → เพลงเดิมที่ต้นเพลง | พบพฤติกรรมย้อนต้นเพลง |
| ก่อนหน้าแบบปรับให้กลับเพลงจริง ขณะหน้าแชทอยู่ด้านหน้า | ตรวจพบย้อนต้นเพลง แล้วส่งอีกครั้ง: ด้วยใจยินดี → Summertime | ผ่าน 1 ครั้ง |

ทุกคำสั่ง API ที่ทดสอบคืนค่า true และมีการตรวจสถานะเพลงแยกต่างหาก ไม่ใช้ true เพียงอย่างเดียวตัดสินว่าผ่าน ค่า foreground window ก่อนและหลังของรอบเบื้องหลังตรงกัน และไม่ใช่หน้าต่าง Apple Music: หน้าทดสอบหมายเลข 461726 และหน้าแชทหมายเลข 133174; Apple Music หมายเลข 1640918

หลักฐานดิบอยู่ใน `connection_events.jsonl` มีเวลาส่งคำสั่ง ข้อมูลก่อน/หลัง และหน้าต่างด้านหน้า

ข้อสรุป: ควบคุม Apple Music ขณะหน้าต่างอื่นอยู่ด้านหน้าได้ในรอบนี้ จึงเดินหน้าสร้างส่วนรู้จำท่ามือได้ ยังไม่ใช่การทดสอบกับกล้องจริงหรือผลประเมินความเสถียรจำนวนมาก ไม่ได้ตรวจเสียงจากลำโพงโดยตรง และยังไม่ได้ทดสอบกรณีปิดแอป คิวจบ หรือเพลงชื่อซ้ำ

คำสั่ง “เพลงก่อนหน้า” ในตัวทดสอบปรับให้ส่งอีกครั้งเฉพาะเมื่อยืนยันว่าเพลงเดิมย้อนกลับต้นเพลงหลังคำสั่งแรก วิธีนี้ต้องตรวจซ้ำในคิวอื่นด้วย การเปรียบเทียบชื่อเพลงยังมีข้อจำกัดเมื่อเพลงชื่อซ้ำ

## ลองด้วยตนเอง

1. เปิด Apple Music และเลือกคิวที่มีหลายเพลง
2. เปิด `เปิดหน้าทดสอบ.cmd` จากโฟลเดอร์ outputs (หน้าทดสอบเปิดไว้แล้วในรอบนี้)
3. กดอ่านสถานะ แล้วลองเล่น/พัก ถัดไป และก่อนหน้า รอผลประมาณ 3 วินาทีต่อคำสั่ง
4. สังเกตว่าหน้าทดสอบยังอยู่ด้านหน้า และชื่อเพลง/สถานะตรงกับเครื่องเล่น

หน้าทดสอบนี้ยังไม่มีระบบกล้องหรือโมเดล AI ปุ่มถูกปิดชั่วคราวขณะรอผลเพื่อป้องกันการกดซ้ำ ส่วนระบบยืนยันท่าและปล่อยมือจะทำในขั้นรู้จำท่ามือ

ติดตั้งไลบรารีเฉพาะใน `.venv` ของโปรเจกต์นี้ รายการรุ่นอยู่ใน `connection_requirements.txt` เมื่อทดสอบจากสภาพแวดล้อมจำกัดของเครื่องมือ Windows API ไม่พบ service แต่ทำงานได้เมื่อเรียกในบัญชีผู้ใช้จริง ผลนั้นไม่ใช่เหตุให้เปลี่ยนการตั้งค่าความปลอดภัย Windows

แหล่งอ้างอิงวิธี API: https://learn.microsoft.com/en-us/uwp/api/windows.media.control.globalsystemmediatransportcontrolssession

## ประวัติรอบตรวจเบื้องต้น (ก่อนรอบยืนยัน)

- การค้นหารายการติดตั้งครั้งแรกไม่พบ Apple Music แต่ผลนั้นไม่ครบ: หลังผู้ใช้เปิดแอป พบหน้าต่าง Apple Music จริง (AppleInc.AppleMusicWin_nzyj5cx40ttqa!App)
- เปิดเพลย์ลิสต์ที่มี 39 เพลงและกด Play ได้ เห็นชื่อเพลงและไอคอนพักเพลงในแถบเครื่องเล่น นี่เป็นหลักฐานสถานะ UI ไม่ใช่การตรวจเสียงจากลำโพง
- พบรายการติดตั้ง iTunes รุ่น 12.13.10.3 ในรายการโปรแกรม Windows การพบรายการนี้ยังไม่ยืนยันว่า iTunes เปิดหรือเล่นเพลงได้
- ส่ง Ctrl+Space 2 ครั้ง แต่ภาพทันทีไม่แสดงสถานะพักที่ชัดเจน จึงยังไม่สรุปว่าผ่าน
- ส่ง Ctrl+Right ได้ 1 ครั้ง แล้วภาพติดตามพบชื่อเพลงเปลี่ยน แต่มีการใช้งานหน้าต่างร่วมกับผู้ใช้ระหว่างรอบ จึงยังไม่แยกผลของคีย์ออกจากการใช้งานอื่นได้อย่างมั่นใจ
- อีกบางคำสั่งถูกเครื่องมือหยุดไว้เพราะตรวจพบ user input; ไม่ถือว่าได้ส่งสำเร็จ
- ยังไม่ได้ทดสอบ Ctrl+Left และยังไม่ได้พิสูจน์การควบคุมเบื้องหลัง
- หน้าต่างเปลี่ยนเป็น MiniPlayer ระหว่างรอบและหายไปก่อนตรวจต่อ การกู้คืนเป้าหมายล้มเหลวด้วยข้อความ `window id 854940 was not found` จึงหยุดการควบคุม ไม่ใช้ตำแหน่งเก่ากดต่อ

ข้อสรุป ณ รอบเบื้องต้น: มีแอปและเปิดเล่นจาก UI ได้ แต่ยังยืนยันการส่งคีย์ไม่ได้ รอบยืนยันด้านบนใช้ API และให้ผลชัดเจนกว่า จึงไม่เลือกคีย์ลัดเป็นวิธีหลัก

## เตรียมทดสอบ

เปิดเครื่องเล่นที่ต้องการใช้จริงและเลือกคิวอย่างน้อย 3 เพลง ผู้ใช้จัดการการเข้าสู่ระบบเอง ตั้งเสียงให้เหมาะกับการทดลอง ไม่ต้องส่งรหัสผ่านหรือข้อมูลบัญชีมาในแชท

คู่มือ Apple Music บน Windows ระบุ:

| คำสั่ง | คีย์ลัด |
|---|---|
| เล่น/พัก | Ctrl+Space |
| เพลงถัดไปขณะกำลังเล่น | Ctrl+ลูกศรขวา |
| เพลงก่อนหน้าขณะกำลังเล่น | Ctrl+ลูกศรซ้าย |

แหล่งอ้างอิง: https://support.apple.com/en-lamr/guide/music-windows/mus1019/windows

คีย์อาจต่างตามภาษาและแป้นพิมพ์ ต้องตรวจผลจริง ไม่ใช้คู่มือนี้เป็นหลักฐานว่า Windows ส่งคีย์เข้าแอปที่อยู่เบื้องหลังได้ และไม่เหมารวมคีย์ของ Apple Music ว่าเป็นคีย์ของ iTunes

## ตารางคีย์ลัดและท่ามือที่ยังไม่ผ่านการยืนยัน

| กรณี | สิ่งที่ต้องสังเกต | ผล |
|---|---|---|
| เล่น/พัก เมื่อเครื่องเล่นอยู่ด้านหน้า | สถานะเปลี่ยน เล่นแล้วเวลาเดิน พักแล้วเวลาหยุด | ส่งคีย์แล้ว แต่ยังยืนยันผลไม่ได้ |
| ถัดไป เมื่อเครื่องเล่นอยู่ด้านหน้า | ชื่อเพลงเปลี่ยนเป็นรายการถัดไป | พบชื่อเพลงเปลี่ยน แต่ต้องทดสอบซ้ำเพื่อแยกสาเหตุ |
| ก่อนหน้า เมื่อเครื่องเล่นอยู่ด้านหน้า | ชื่อเพลง/ตำแหน่งเปลี่ยนอย่างไร รวมพฤติกรรมย้อนต้นเพลง | ยังไม่ได้ทดสอบ |
| เล่น/พัก เมื่อหน้าต่างเดโมอยู่ด้านหน้า | เพลงเปลี่ยนสถานะโดยไม่แย่งหน้าต่างหรือไม่ | ยังไม่ได้ทดสอบ |
| ถัดไป เมื่อหน้าต่างเดโมอยู่ด้านหน้า | ชื่อเพลงเปลี่ยนและหน้าต่างเดโมยังอยู่ด้านหน้าหรือไม่ | ยังไม่ได้ทดสอบ |
| ก่อนหน้า เมื่อหน้าต่างเดโมอยู่ด้านหน้า | เปลี่ยนเพลงหรือย้อนต้นเพลง หน้าต่างใดรับคีย์ | ยังไม่ได้ทดสอบ |
| ค้างท่าหลังระบบกล้องพร้อม | ส่งเพียง 1 คำสั่งจนกว่าจะปล่อยท่า | รอระบบกล้อง |
| ปล่อยแล้วทำท่าอีกครั้ง | ส่งคำสั่งใหม่ได้ 1 ครั้ง | รอระบบกล้อง |
| ไม่เห็นมือ/ท่าอื่น | ไม่มีคำสั่งเพลง | รอระบบกล้อง |

บันทึกแต่ละครั้งด้วยชื่อแอป วิธีส่งคำสั่ง หน้าต่างด้านหน้า สถานะก่อน/หลัง และผลสำเร็จ/ผิดพลาด ต้องตรวจทั้ง 3 คำสั่งก่อนเลือกวิธีเชื่อมต่อหลัก
