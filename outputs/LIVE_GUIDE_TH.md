# ทดลองควบคุมเพลงด้วยกล้องสด

เปิด `start_music_controller.cmd` ในโฟลเดอร์ outputs หน้าทดลองจะเริ่มในโหมดดูผล ยังไม่ส่งคำสั่งเพลง

1. เปิดกล้อง แล้วลองกำมือ ชูสองนิ้ว และชูนิ้วโป้ง ทีละข้าง ตรวจชื่อท่าบนหน้าจอ
2. คงท่าประมาณ 0.6 วินาทีให้ระบบยืนยัน เอามือออกจากภาพประมาณครึ่งวินาทีก่อนทำท่าถัดไป ค้างมือหรือเปลี่ยนจากท่าคำสั่งหนึ่งไปอีกท่าโดยไม่ปล่อยจะไม่สั่งซ้ำ
3. เปิด Apple Music และคิวหลายเพลง กด “อ่านสถานะ Apple Music” เพื่อตรวจการเชื่อมต่อ
4. เมื่อพร้อม กด “เริ่มควบคุมเพลง” แล้วเอามือออกก่อนเริ่ม ทำท่าเพื่อเล่น/พัก ถัดไป และก่อนหน้า
5. กด “พักการควบคุม” ได้ทุกเมื่อเพื่อกลับโหมดดูผล หากส่งผิด ให้พักแล้วแจ้งท่า ข้างมือ และสิ่งที่เกิดขึ้น อย่าเปลี่ยนค่าจากคะแนน test เพื่อแก้เฉพาะชุดนั้น

รุ่นปรับล่าสุดรับสองมือในภาพ โดยกรอบสีเขียวระบุมือสั่งงาน สองมือที่ทำคำสั่งต่างกันจะไม่ส่งเพลง ไม่เห็นมือ คะแนนไม่ถึงเกณฑ์ หรือภาพกล้องขาดช่วงจะไม่ส่งคำสั่ง รายละเอียดและวิธีเก็บท่าสามนิ้วเพิ่มเติมอยู่ใน LIVE_FIXES_TH.md

คะแนนที่เห็นเป็นคะแนนโมเดล ไม่ใช่โอกาสถูกที่สอบเทียบแล้ว ตัวจำแนกเรียนรู้จากพิกัดมือของผู้ใช้ 3,160 ตัวอย่าง ส่วน MediaPipe เป็นตัวสกัดตำแหน่งมือสำเร็จรูป

## ผลจำแนกที่ได้ก่อนเดโม

- ฝึกจาก train 1,893 ตัวอย่าง เลือกโมเดลด้วย validation 633 ตัวอย่าง
- เลือก Logistic Regression C=1 เมื่อผล validation เท่ากันกับโมเดลที่ซับซ้อนกว่าบางตัว โดยกำหนดลำดับการตัดสินเสมอไว้ก่อน
- โมเดลที่เลือกจำแนก test ถูก 634/634 เฟรม (ขวา 322/322, ซ้าย 312/312)
- เฟรมติดกันมีความสัมพันธ์กัน และมีเพียงผู้ใช้คนเดียวในสภาพใกล้กัน ผล 100% จึงไม่ได้แปลว่าสั่งเพลงจริงถูกทุกครั้งหรือใช้ได้กับทุกคน
- ผลการจำแนกไม่ใช่ผลการสั่งเพลง ต้องประเมินการยืนยันท่าและการตอบสนองของ Apple Music แยกกัน

รายละเอียดอยู่ใน models/20261004_171415/MODEL_REPORT_TH.md ข้อมูลเดิมไม่ถูกแก้ และแต่ละรอบคงอยู่ในชุดเดิม

## ตารางสำหรับทดสอบการสั่งงานจริง

ทำอย่างน้อยคำสั่งละ 5 ครั้งต่อข้าง รวม 30 ครั้ง เพื่อเริ่มประเมิน ไม่เลือกนับเฉพาะครั้งที่สำเร็จ บันทึกทุกครั้งที่ตั้งใจทำ รวมครั้งที่ระบบไม่ส่งหรือส่งผิด ระบบบันทึกคำสั่งที่ตรวจพบและผลเครื่องเล่นใน live_command_events.jsonl แต่ไม่รู้ว่าผู้ใช้ตั้งใจทำอะไร จึงต้องบันทึก intention แยกในตารางนี้

| ครั้ง | ข้างจริง | คำสั่งที่ตั้งใจ | คำสั่งที่ระบบส่ง/ไม่ส่ง | ผลเพลง | คำสั่งซ้ำ | เวลาตอบสนอง/หมายเหตุ |
|---|---|---|---|---|---|---|
| 1 | | | | | | |

ทดลองเพิ่มเติม: ค้างท่า 3–5 วินาทีควรมีเพียงคำสั่งเดียว; ปล่อยแล้วทำซ้ำควรได้คำสั่งใหม่; ไม่เห็นมือ/มือสองข้าง/ท่าอื่นควรไม่มีคำสั่งเพลง บันทึกเวลาสังเกตและสภาพแสงด้วย

คำสั่งก่อนหน้าตรวจกรณี Apple Music ย้อนต้นเพลงก่อน แล้วส่งอีกครั้งเมื่อยืนยันพฤติกรรมนี้ การเปรียบเทียบชื่อเพลงยังมีข้อจำกัดกับชื่อซ้ำ คำสั่งผิดพลาดจะไม่ถูกส่งซ้ำอัตโนมัติ
