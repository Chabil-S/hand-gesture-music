# ท่าเพิ่มเติม: จีบปรับเสียง และแบมือพัก/เริ่ม

จีบปรับเสียงและแบมือพัก/เริ่มเป็นท่าควบคุมปกติ ใช้ร่วมกับกำมือ เล่น/พัก, V ถัดไป และชูโป้ง ก่อนหน้าในโหมดเดียว เปิดทั้งสองไว้เป็นค่าเริ่มต้น ระบบยังใช้พิกัดข้อต่อสำหรับสองท่านี้ และใช้โมเดลเดิมสำหรับท่าเพลง โดยไม่เปลี่ยนคะแนนขั้นต่ำหรือข้อมูลฝึก

## เริ่มใช้งาน

1. เปิด Apple Music และเริ่มเพลง แล้วเปิด `outputs/start_music_controller.cmd` ใหม่
2. กด **เปิดกล้อง** แอปเริ่มในโหมดดูผล
3. กด **เริ่มควบคุมเพลง** หรือเอามือออกก่อนแล้วแบมือค้าง 1.2 วินาที
4. ปล่อยมือก่อนเริ่มท่าคำสั่ง เพลงและเสียงจะเริ่มตอบสนองเมื่อเปิดการควบคุมแล้ว

ไม่ต้องเลือกโหมดแยกเพื่อปรับเสียง ระบบรับจากท่าที่ทำอยู่ ถ้าต้องการปิดจีบหรือแบมือ ไปที่ **ตั้งค่า → ท่าควบคุม** แล้วกด **บันทึกท่าควบคุม** ตัวเลือกจำไว้เมื่อเปิดโปรแกรมใหม่ใน `outputs/gesture_options.json` แยกจากค่ารับท่าและไม่ส่งเข้า Git การบันทึกตัวเลือกจะพักการควบคุมและกลับโหมดดูผล ปุ่มเพลงบนหน้า Now playing ยังสั่งงานได้ตามเดิม

## ท่าที่ใช้ร่วมกัน

| ท่า | ผล |
|---|---|
| กำมือ | เล่น / พักเพลง |
| V ชี้–กลาง พับโป้ง | เพลงถัดไป |
| ชูโป้ง | เพลงก่อนหน้า |
| จีบชี้–โป้ง พับอีกสามนิ้ว | กางเพิ่มเสียง / หุบลดเสียง |
| แบทั้งห้านิ้วค้าง 1.2 วินาที | พัก / เริ่มการควบคุมทั้งหมด |

ตอนทำท่าจีบหรือแบมือ ระบบกันท่าเพลงที่ตัวจำแนกอาจอ่านระหว่างขยับนิ้วไว้ จบท่าจีบแล้วต้องเอามือออกหรือทำท่าไม่สั่งงานตามเวลาปล่อยมือใน Settings ก่อนเริ่มท่าใหม่ การหุบต่อเป็นกำมือทันทีจึงไม่กลายเป็นเล่น/พัก เมื่อสั่งเพลงแล้วต้องปล่อยก่อนเริ่มจีบเช่นกัน

มีสองมือในเฟรมได้ ระบบติดตามมือที่รับคำสั่งอยู่ แม้ลำดับตรวจมือเปลี่ยน ถ้าสองมือแสดงคนละคำสั่ง รวมถึงจีบ/แบมือ ระบบจะรอให้เหลือท่าคำสั่งเดียว

## จีบเพิ่ม/ลดเสียง

- พับนิ้วกลาง นาง และก้อย เหลือนิ้วชี้กับโป้ง อย่าใช้ท่า V
- **เพิ่ม:** เริ่มให้ปลายชี้–โป้งแตะกัน ค้างประมาณ **0.45 วินาที** รอข้อความให้กาง แล้วค่อยกางออก
- **ลด:** เริ่มกางชี้–โป้ง ค้างประมาณ **0.45 วินาที** แล้วค่อยหุบเข้าหากัน
- กางชี้–โป้งได้เต็มระยะตามธรรมชาติ ไม่ต้องจำกัดให้เป็นรูป C ตราบใดที่อีกสามนิ้วยังพับและกล้องเห็นข้อต่อชัด ระบบไม่ตัดท่าด้วยเพดานระยะชี้–โป้ง
- ระยะที่ขยับมากขึ้นเปลี่ยนเสียงมากขึ้น การนิ่งไว้คงเสียงเดิม เอามือออกเพื่อจบ แล้วเริ่มท่าใหม่ได้
- ในโหมดดูผล ข้อความบอกทิศเพิ่ม/ลด แต่เสียงจริงไม่เปลี่ยน
- ระบบกันคำสั่งเพลงเฉพาะช่วงที่กำลังทำท่าจีบ ปล่อยมือแล้วกลับใช้กำมือ/V/ชูโป้งได้ทันทีโดยไม่เปลี่ยนโหมด
- ต้องใช้ทั้งนิ้วชี้และโป้ง นิ้วชี้เดี่ยวโดยพับโป้งไม่ใช้เริ่มปรับเสียง

ปรับเสียง **audio session ของ Apple Music ใน Windows Volume Mixer** โดยตรวจทั้งชื่อโปรเซสและ package ของ Apple Music ก่อนส่งคำสั่ง ไม่ใช้เสียงรวมเครื่องเป็นทางสำรอง ไม่ปลด mute และไม่เปลี่ยนเสียงแอปอื่น แถบเสียงภายใน Apple Music อาจไม่ขยับตาม ให้ดูระดับเสียงที่หน้า Gesture Music หรือ Windows Volume Mixer

Apple Music รุ่นที่ตรวจบนเครื่องนี้เล่นเพลงผ่าน `AMPLibraryAgent.exe` ในแพ็กเกจ Apple Music เดียวกัน ระบบรับช่องเสียงจากทั้ง `AppleMusic.exe` และโปรเซสช่วยนี้ แล้วเลือกช่องที่กำลังเล่นเสียงก่อนช่องที่ค้างอยู่แต่ไม่ได้เล่น หากมีหลายช่องกำลังเล่นพร้อมกันจะยังไม่ปรับ เพื่อป้องกันการเลือกผิดช่อง ระหว่างพักเพลงอาจอ่านระดับไม่ได้จนเริ่มเล่นอีกครั้ง

ถ้าแสดง “ยังอ่านไม่ได้” ให้เริ่มเพลงใน Apple Music เอามือออก แล้วรอประมาณสองวินาทีเพื่ออ่านใหม่ หากพบ session มากกว่าหนึ่งอัน ระบบจะพักการปรับเสียงเพื่อไม่เลือกผิด ถ้าระดับเสียงอยู่ 100% แล้ว การกางเพิ่มจะไม่ทำให้ดังขึ้นอีก สามารถเริ่มลองจากการหุบลดก่อน

ระบบหารระยะนิ้วด้วยขนาดฝ่ามือเพื่อช่วยลดผลจากการขยับเข้า/ออกกล้อง กรองการสั่น และส่งได้ประมาณทุก 0.12 วินาที ครั้งละไม่เกิน **3 จุดเปอร์เซ็นต์** เมื่อมือหาย เปลี่ยนมือ ภาพขาด หรือพักการควบคุม จะยกเลิกงานที่ยังรอและเริ่มจับท่าใหม่ งานที่เริ่มเขียนระดับเสียงแล้วอาจจบหนึ่งขั้น

## แบมือพัก/เริ่มควบคุม

- ท่านี้เปิดเป็นค่าเริ่มต้น ปิดเฉพาะท่าแบมือได้ใน **ตั้งค่า → ท่าควบคุม**
- เปิดกล้องไว้ เอามือออกก่อน แล้ว **กางทั้งห้านิ้วค้าง 1.2 วินาที**
- ถ้ากำลังควบคุม จะกลับโหมดดูผล ถ้าอยู่โหมดดูผล จะเริ่มควบคุม
- ระหว่างค้างจะเห็นเวลานับและแถบความคืบหน้าทั้งหน้าจับท่าทางและหน้า Now playing เมื่อครบจะแสดง “เริ่มควบคุมแล้ว” หรือ “พักการควบคุมแล้ว” ค้างไว้จนปล่อยมือ ถ้ายังไม่ได้ปล่อยก่อนเริ่ม จะแจ้งให้ปล่อยโดยไม่แสดงแถบเต็มว่าได้รับคำสั่งแล้ว
- ปล่อยมืออย่างน้อย **0.35 วินาที** ก่อนแบมือครั้งใหม่ ค้างมือไว้ไม่สลับซ้ำ
- หลังเริ่มควบคุมด้วยแบมือ ต้องปล่อยก่อนทำท่าเพลง เพื่อไม่ให้ท่าที่ค้างอยู่สั่งงานทันที
- ขณะพัก ระบบยังตรวจแบมือเพื่อเริ่มใหม่ได้ **ตราบใดที่กล้องยังเปิด** ปิดกล้องแล้วต้องเปิดด้วยปุ่ม
- ถ้าไม่เปิดตัวเลือกนี้ การแบมือยังเป็นท่าไม่สั่งงานแบบเดิม

## ตรวจการใช้งานร่วมกัน

ท่าจีบหรือแบมือที่เริ่มทำแต่ยังไม่ยืนยันจะไม่ล็อกท่าเพลง การปล่อยมือที่กล้องตรวจพบยังนับเวลาได้เมื่อภาพมาช้า โดยภาพขาดเพียงอย่างเดียวจะไม่ปลดล็อกให้ส่งคำสั่ง การปรับเสียงตรวจช่องเสียง Apple Music โดยตรง ไม่ขึ้นกับว่าหน้าจออ่านชื่อเพลงสำเร็จหรือไม่ หากปรับไม่ได้จะแสดงเหตุผล และบันทึกผลการปรับจริงใน `outputs/live_command_events.jsonl` เป็นรายการ `volume_result`

ลองกำมือ → ปล่อย → V → ปล่อย → จีบปรับเสียง → ปล่อย → ชูโป้ง ทั้งสองมือ จากนั้นใช้แบมือพักแล้วเช็กว่าท่าเพลงและจีบไม่ส่งคำสั่ง ใช้แบมือเริ่มใหม่และปล่อยก่อนทำท่าคำสั่งอีกครั้ง หากมีท่าหลุด จดมือ ท่า มุม และข้อความที่เห็นเพื่อระบุจุดแก้ ไม่จำเป็นต้องถ่ายข้อมูลใหม่ก่อนเห็นปัญหา

## ปรับค่าท่าเอง

ยังไม่มีช่องปรับตัวเลขชุดนี้ใน UI ค่าท่าสองประเภทนี้อยู่ใน `outputs/dynamic_gestures.py` แยกจากคะแนนขั้นต่ำและเวลาท่าเพลงใน Settings ปิดแอปก่อนแก้แล้วเปิดใหม่

| ค่าเริ่มต้น | ตำแหน่ง | ผลเมื่อปรับ |
|---|---|---|
| เริ่มจีบ 0.45 วินาที | `PinchVolume(hold=.45)` | เพิ่มเพื่อกันการเริ่มโดยไม่ตั้งใจ ลดเพื่อเริ่มเร็วขึ้น |
| ความไว .25 | `PinchVolume(gain=.25)` | ระยะนิ้ว 1 หน่วยฝ่ามือเทียบประมาณ 25 จุดเปอร์เซ็นต์ก่อนจำกัดต่อขั้น; เพิ่มทำให้ไวขึ้น |
| ระยะนิ่ง .035 | `PinchVolume(deadband=.035)` | เพิ่มเพื่อลดการสั่น ลดเพื่อรับการขยับละเอียด |
| เว้นส่ง .12 วินาที | `PinchVolume(interval=.12)` | เพิ่มทำให้ส่งถี่น้อยลง |
| สูงสุด .03 ต่อขั้น | `PinchVolume(max_step=.03)` | ตัวส่งเสียงจำกัดไว้ .03 อีกชั้น อย่าเพิ่มเกินนี้โดยไม่ทบทวนตัวส่งและทดสอบ |
| แบมือ 1.2 วินาที | `PalmControl(hold=1.2)` | เพิ่มเพื่อกันสลับโหมดโดยไม่ตั้งใจ |
| ปล่อยแบมือ .35 วินาที | `PalmControl(release=.35)` | เวลาปล่อยก่อนอนุญาตให้สลับโหมดอีกครั้ง |
| ภาพขาด .3 วินาที | `max_gap=.3` ของทั้งสองตัวตรวจ | เว้นเกินนี้เริ่มจับท่าใหม่; การขาดภาพยังถูกเฝ้าด้วยค่าระบบหลัก |

เกณฑ์เริ่มจีบ/กางและมุมข้อต่อนิ้วใน `geometry()` ควรปรับจากผลใช้งานจริง ค่าทั้งสองท่านี้ไม่ใช่ความแม่นยำของโมเดลเดิม ช่องคะแนนโมเดลซ่อนเฉพาะตอนทำจีบ/แบมือ เพราะไม่ได้ใช้คะแนนตัวจำแนกมาตัดสินท่าเหล่านี้ แล้วกลับมาแสดงเมื่อใช้ท่าเพลง

อ้างอิงช่องทางเสียง: [Microsoft: GetProcessId](https://learn.microsoft.com/en-us/windows/win32/api/audiopolicy/nf-audiopolicy-iaudiosessioncontrol2-getprocessid) และ [ISimpleAudioVolume](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-isimpleaudiovolume-setmastervolume)
