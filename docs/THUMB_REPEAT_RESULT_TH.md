## รอบสอง: 20261005_200323_6720d6c7

605 เฟรม ช่องว่างภาพสูงสุด 0.110 วินาที ผู้ใช้ยืนยัน **รอบสองทำตามหน้าจอครบ** จึงไม่ติดป้ายว่าผู้ใช้ทำจังหวะผิด

ซ้ายรุ่นทดลองส่ง previous 3.968 และ 11.093 วินาทีใน hold ครบ 2/2; ช่วง hold ตรงป้าย 98/98 และปล่อย neutral 64/64

ขวารุ่นทดลองส่ง previous 5.016 วินาทีใน hold และ 15.016 วินาทีใน release ทั้งสามรุ่นส่งครั้งที่สองใน release เหมือนกัน ไม่สรุปว่าเป็นผลผ่านจากจำนวนคำสั่งสองครั้งเพียงอย่างเดียว รอบนี้ยังเป็นปัญหาที่ต้องตรวจ

ตรวจพิกัด: ช่วง hold ครั้งที่สอง 11–13.75 วินาที เส้นนิ้วทั้งสี่มีอัตราเหยียดเกือบหนึ่ง (ประมาณ 0.996–0.999) และทุกโมเดลอ่าน neutral ขณะที่ช่วง release ครั้งที่สองพิกัดนิ้วงอและทุกโมเดลอ่าน previous รูปเส้นมือเป็นข้อมูลที่ MediaPipe ประเมิน ไม่ใช่ภาพจริง จึงยังแยกไม่ได้ว่าเกิดจากตัวตรวจมือ จังหวะที่หน้าจอแสดง หรือสาเหตุอื่น ไม่ใช้โมเดลสามตัวที่รับพิกัดชุดเดียวกันเป็นหลักฐานอิสระว่าผู้ใช้ทำผิด

## สิ่งที่แก้ในหน้าทดสอบ

เดิมหัวข้อใหญ่ค้างชื่อท่าชูโป้งทั้งช่วงทำและปล่อย ข้อความเปลี่ยนอยู่ในตัวนับเวลาเท่านั้น ทำให้มีข้อความสองจุดที่อาจสับสน แต่ยังไม่พิสูจน์ว่านี่เป็นสาเหตุของรอบสอง เปลี่ยนหัวข้อใหญ่ให้เป็นท่าที่ต้องทำตอนนั้น: เตรียม/ปล่อยแสดงแบมือ ช่วงทำแสดงชูโป้ง แก้ตัวนับช่วงจาก /10 เป็นจำนวนจริง /2 ในหน้าทวน และบันทึก phase ตามเวลาแสดงหน้าจอพร้อมอายุภาพเมื่อประมวลผล เพื่อช่วยตรวจความต่างของเวลาในรอบต่อไป

ไม่เปลี่ยนโมเดล เกณฑ์คะแนนหรือระยะค้าง/ปล่อย ผลรอบแรกดีขึ้น แต่ยังไม่ประกาศผ่านทั้งหมด: validation ชูโป้งขวายังคง 89.9% และอาการขวารอบสองยังไม่ทราบสาเหตุ ไม่ขอถ่ายข้อมูลฝึกเพิ่มโดยไม่ทราบว่ากำลังเติมปัญหาอะไร
