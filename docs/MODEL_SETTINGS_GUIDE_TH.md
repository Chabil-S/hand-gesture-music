# ตั้งรุ่นทดลองใช้ด้วยเป้าหมายรับท่า 85%

ปรับตามคำขอผู้ใช้จากเป้าหมายรับแต่ละคำสั่ง 95% เป็น **85%** และเปิดรุ่นที่ทดสอบ 20261005_194641 สำหรับลองควบคุม Apple Music ไม่ถ่ายหรือฝึกเพิ่ม

## เปลี่ยนตรงไหน

ไฟล์ตั้งเป้าหมาย: **D:\hand-gesture-music\outputs\acceptance_policy.json**

```json
"minimum_command_recall": 0.85
```

หมายถึงใน validation แต่ละคำสั่งของแต่ละมือ ต้องมีเฟรมที่รับท่าถูกอย่างน้อย 85% (0.85 = 85%, 0.90 = 90%, 0.95 = 95%) ไม่ใช่ความแม่นของทุกคนหรือทุกสภาพแสง คะแนนชูโป้งขวาของรุ่นนี้ 142/158 หรือ 89.9% จึงผ่าน 85% แต่ยังไม่ผ่าน 90% หรือ 95%

เปลี่ยนฟังก์ชันตรวจใน outputs/revision_validation.py ให้รับ minimum_command_recall เป็นตัวเลือก โดยค่าเริ่มต้นยัง 0.95 รุ่นนี้ส่งค่า 0.85 จากไฟล์นโยบายเท่านั้น ไม่ลดเกณฑ์ทั้งระบบโดยไม่ตั้งใจ

ตรวจ validation ใหม่จากไฟล์และแฮชเดิม ไม่เปิด test เงื่อนไขอื่นคงเดิม: ไม่มีคำสั่งจริงผิดจากสามนิ้ว/neutral, neutral ปกติรับ >=95%, ทุกคลิปคำสั่งออกถูกหนึ่งครั้งภายใน 1.5 วินาที และต่อคำสั่ง–ปล่อย–คำสั่งได้ครบ รุ่นนี้ผ่านทั้งหมดภายใต้เป้าหมายใหม่

สำเนารุ่นเปิดใช้ **D:\hand-gesture-music\outputs\models\reviewed_20261005_202001** เก็บโมเดลไฟล์เดียวกับ 194641 (SHA เดิม) แต่มีผลประเมินภายใต้นโยบายใหม่และประวัติรุ่นก่อนหน้า แหล่งต้นฉบับรุ่นทดลองกับรายงาน 95% เดิมไม่ถูกแก้ไข

ตัวชี้ **D:\hand-gesture-music\outputs\latest_model.json** เปลี่ยนจาก models\20261004_221121 เป็น models\reviewed_20261005_202001 รุ่นเก่ายังคงอยู่ ผล full_validation_passed ของสำเนาหมายถึงผ่านนโยบาย 85% นี้ ไม่ได้หมายความว่าผ่านเป้าหมายเดิม 95% หรือผ่านการทดสอบอิสระครบระบบแล้ว

## ปรับเองครั้งต่อไป

1. ปิดหน้าควบคุมเพลงก่อน
2. เปิด acceptance_policy.json ด้วย Notepad เปลี่ยนเฉพาะ minimum_command_recall เช่น 0.85 แล้วบันทึก คงเครื่องหมาย comma ตามรูปแบบ JSON
3. เปิด **D:\hand-gesture-music\outputs\update_model_acceptance.cmd** ตัวนี้ตรวจรุ่น 194641 ซ้ำและสร้างสำเนาที่ผ่านนโยบายใหม่ก่อนสลับรุ่น ไม่ฝึกและไม่ใช้ test ถ้าไม่ผ่าน ตัวชี้รุ่นใช้งานจะคงเดิม ดูรายละเอียดใน outputs\acceptance_update.log
4. เปิด **D:\hand-gesture-music\outputs\start_music_controller.cmd** ใหม่ การแก้ JSON อย่างเดียวไม่สลับรุ่นที่เปิดค้างอยู่ และยังไม่สร้างผลประเมินใหม่จนกดตัวปรับเกณฑ์

ค่าที่เหลือใน acceptance_policy.json เป็นคำอธิบายนโยบายปัจจุบัน ไม่ใช่ตัวปรับพฤติกรรมขณะเล่น ตัวปรับนี้รับเฉพาะ minimum_command_recall สำหรับรุ่น 194641

## ต่างจากคะแนนรับท่าตอนเล่นอย่างไร

| ค่า | ปัจจุบัน | ความหมาย |
|---|---:|---|
| minimum_command_recall | 0.85 | เป้าหมายผ่านการประเมินก่อนเปิดใช้ |
| threshold | 0.80 | คะแนนโมเดลขั้นต่ำเพื่อยอมรับท่าในแต่ละเฟรม |
| hold_seconds | 0.60 | ต้องคงท่าต่อเนื่องนานเท่าไรจึงส่งคำสั่ง |
| release_seconds | 0.35 | ต้องปล่อยเป็น neutral/ไม่เห็นมือเท่าไรจึงรับคำสั่งใหม่ |
| max_frame_gap_seconds | 0.30 | ช่องว่างภาพสูงสุดก่อนเริ่มนับท่ายืนยันใหม่ |

threshold/hold/release อยู่ใน selection_frozen.json ของรุ่นที่ latest_model.json ชี้อยู่ ใช้เพื่อดูค่าที่รุ่นนั้นประเมินไว้ ไม่ใช่ minimum_command_recall การลดเป้าหมาย 95→85% ไม่ทำให้โมเดลรับท่าง่ายขึ้นโดยตรง ประสบการณ์ที่ดีขึ้นมาจากเปลี่ยนไปใช้รุ่นที่ฝึกและทดสอบล่าสุด คะแนนโมเดลไม่ใช่โอกาสถูกที่สอบเทียบแล้ว

ไม่แนะนำแก้ selection_frozen.json ทับผลเดิมเพื่อปรับพฤติกรรม หากต้องการเปลี่ยน threshold หรือเวลาค้างจริง ต้องใช้สำเนาค่าตั้งใหม่และตรวจผลคำสั่งผิด/ซ้ำอีกครั้ง รายงานที่มีอยู่ไม่ครอบคลุมค่าที่เปลี่ยน

## เริ่มลองใช้งาน

เปิด Apple Music และเลือกคิวเพลงอย่างน้อย 3 เพลง ปิดหน้าทดสอบกล้องอื่น start_music_controller.cmd เปิดกล้อง แล้วกดเริ่มควบคุมเพลง: กำมือเล่น/พัก, V ถัดไป, ชูโป้งก่อนหน้า ระหว่างคำสั่งให้แบมือหรือเอามือออก ถ้าต้องการหยุดส่งคำสั่งให้กลับโหมดดูผล

ตรวจแล้วว่าหน้าควบคุมจริงโหลดรุ่นใหม่ได้และเริ่มด้วยกล้องปิด/ยังไม่ส่งเพลง ประวัติเปิด test ไม่เปลี่ยน การทดสอบนี้ยังต้องดูผลจริงของ Apple Music เช่นคำสั่งสำเร็จ คำสั่งซ้ำหรือเพลงข้ามเมื่อสามนิ้ว
