# ตั้งค่าการรับท่าขณะควบคุมเพลง

ตั้ง **คะแนนรับท่าขณะใช้งานเป็น 95%** แล้วตามคำขอ ปรับเองได้โดยไม่ผ่านการตรวจ 95% ของชุด validation อีก ค่านี้แยกจากเป้าหมายประเมินรุ่นโดยตรง ไม่เปลี่ยนไฟล์โมเดลหรือผลที่เคยรายงาน

## วิธีปรับจากหน้าจอ

1. ปิดหน้าควบคุมเพลงเก่า แล้วเปิด **D:\hand-gesture-music\outputs\start_music_controller.cmd**
2. เลือกเมนู **ตั้งค่า** ทางซ้าย จะเห็นคะแนนและเวลาค้าง/ปล่อยมือ ส่วนช่องว่างภาพอยู่ใน **การตั้งค่าเพิ่มเติม** ดู [คู่มือหน้าจอใหม่](UI_GUIDE_TH.md)
3. ในช่องคะแนนใส่จำนวนเปอร์เซ็นต์ เช่น **95** ไม่ใช่ 0.95 ส่วนช่องเวลาใส่วินาที เช่น **0.6**
4. กด **บันทึกและใช้ค่า** ใช้ได้ทันทีและบันทึกไว้สำหรับครั้งหน้า ไม่ต้องกด update_model_acceptance.cmd
5. โปรแกรมจะพักการควบคุม กลับโหมดดูผล และเริ่มนับท่าใหม่ ลองทำท่าก่อน แล้วกดเริ่มควบคุมเพลงอีกครั้ง

กด **คืนค่าที่รุ่นเคยทดสอบ** เพื่อเติมค่าที่รุ่นนั้นเคยทดสอบลงในช่อง สำหรับรุ่นปัจจุบันคือ 80%, ค้าง 0.6, ปล่อย 0.35, ช่องว่างภาพ 0.3 วินาที ต้องกดบันทึกและใช้ค่าอีกครั้งจึงมีผล สลับออกจากหน้าตั้งค่าโดยไม่บันทึกจะไม่เปลี่ยนค่าที่ใช้งาน

การพักจะยกเลิกคำสั่งที่ยังรอส่ง แต่คำสั่งที่ส่งให้ Apple Music ไปแล้วอาจทำงานจนจบ ไม่ควรเข้าใจว่าปุ่มตั้งค่าย้อนคำสั่งที่ส่งไปแล้วได้

## 1. คะแนนขั้นต่ำรับท่า

ค่าตอนนี้ **95%** ระบบให้โมเดลอ่านแต่ละเฟรม ถ้าท่าที่ได้คะแนนสูงสุดมีคะแนนต่ำกว่าเกณฑ์ จะขึ้น **ยังไม่แน่ใจ** และไม่เริ่ม/ไม่ต่อการนับท่าคำสั่ง

ตัวอย่าง: ตั้ง 95%, โมเดลอ่านชูโป้งได้ 92% → ยังไม่แน่ใจ; อ่านได้ 97% → เริ่มนับว่าคงท่าชูโป้งนานพอหรือยัง ไม่ได้ส่งเพลงทันทีเมื่อผ่านคะแนน

เพิ่มคะแนน เช่น 80→95 ทำให้รับท่าเข้มงวดขึ้น อาจลดการยอมรับท่าที่คะแนนต่ำ แต่ไม่ได้ฝึกให้โมเดลเก่งขึ้นและไม่ได้รับประกันว่าไม่สั่งผิด ถ้าท่าผิดได้คะแนนสูงก็ยังผ่านได้ คะแนนโมเดลไม่ใช่อัตราถูกที่สอบเทียบแล้ว

ลดคะแนน เช่น 95→90→85 ช่วยให้ท่าที่คะแนนต่ำผ่านได้ง่ายขึ้น แต่ต้องลองว่าท่าอื่นหรือสามนิ้วเริ่มสั่งผิดหรือไม่ ระหว่างลองให้ใช้โหมดดูผลก่อน

เกณฑ์นี้ใช้กับ neutral ด้วย ถ้าแบมือแล้วขึ้นยังไม่แน่ใจ ระบบจะไม่ถือว่าปล่อยท่าสำเร็จ ต้องแบให้ชัดหรือเอามือออกจากภาพ ไม่ใช้คำว่า “ยังไม่แน่ใจ” เป็นการปล่อย เพราะอาจทำให้ค้างท่าแล้วส่งซ้ำ

## 2. เวลาค้างท่า

ค่าตอนนี้ **0.6 วินาที** ต้องอ่านเป็นคำสั่งเดียวกันต่อเนื่องอย่างน้อยเท่านี้จึงส่งหนึ่งคำสั่ง คะแนนต่ำกว่าเกณฑ์หรือเปลี่ยนไปท่าอื่นจะเริ่มนับใหม่

ลด เช่น 0.6→0.4 อาจสั่งเร็วขึ้น แต่ท่าชั่วครู่ตอนขยับมือก็มีโอกาสยืนยันเป็นคำสั่งมากขึ้น เพิ่ม เช่น 0.6→0.8 ต้องค้างชัดนานขึ้น แต่ถ้าท่าขึ้นยังไม่แน่ใจเป็นพัก ๆ การเพิ่มเวลาอาจยิ่งทำให้สั่งยาก

เวลาค้างไม่ใช่เวลารอ Apple Music ส่ง/ตรวจคำสั่ง การส่งเพลงมีเวลาของตัวเองแยกออกไป

## 3. เวลาปล่อยมือ

ค่าตอนนี้ **0.35 วินาที** หลังส่งคำสั่งระบบจะล็อกไว้เพื่อไม่ให้ค้างท่าแล้วส่งซ้ำ ต้องอ่าน neutral หรือไม่เห็นมืออย่างต่อเนื่องครบเวลานี้ก่อนรับคำสั่งใหม่ เปลี่ยนจากชูโป้งไป V ทันทีไม่ถือว่าปล่อย

ลด เช่น 0.35→0.2 พร้อมรับคำสั่งถัดไปเร็วขึ้น แต่ถ้าโมเดลอ่าน neutral สั้น ๆ ระหว่างค้างท่า อาจปลดล็อกและส่งท่าเดิมอีกครั้ง เพิ่ม เช่น 0.35→0.5 ต้องแบมือ/เอามือออกนานขึ้น แต่ช่วยลดการปลดล็อกจาก neutral ชั่วครู่

ตอนกดเริ่มควบคุมก็ต้องปล่อยมือครบเวลานี้ก่อน เพื่อไม่ส่งท่าที่ค้างอยู่ตอนกดเริ่มโดยไม่ตั้งใจ

## 4. ช่องว่างภาพสูงสุด

ค่าตอนนี้ **0.3 วินาที** ถ้าภาพที่ประมวลผลห่างกันเกินค่านี้ ระบบทิ้งเวลาที่กำลังนับท่าค้างและปล่อย แล้วเริ่มใหม่ ไม่รวมเวลาที่ไม่เห็นภาพเข้ากับการยืนยันท่า

ค่านี้เกี่ยวกับความต่อเนื่องของกล้อง ไม่ใช่ระยะมือจากกล้องหรือเวลาส่งเพลง ปกติควรคง 0.3 ไว้ ลดมากเกินไปอาจเริ่มนับใหม่บ่อย เพิ่มมากอาจนับช่วงภาพที่ห่างกันเป็นท่าต่อเนื่อง ทั้งช่องตั้งค่าและตัวตรวจภาพค้างในหน้าควบคุมใช้ค่าเดียวกันแล้ว

ระบบเลือกมือสั่งงานและการป้องกันสองมือทำคำสั่งต่างกันยังใช้ตรรกะเดิม ไม่ได้ปรับด้วยค่านี้

## ปรับจากไฟล์โดยไม่เปิดช่องตั้งค่า

ไฟล์ **D:\hand-gesture-music\outputs\live_settings.json** ตอนนี้:

```json
{
  "threshold": 0.95,
  "hold_seconds": 0.6,
  "release_seconds": 0.35,
  "max_frame_gap_seconds": 0.3
}
```

ในไฟล์คะแนนใช้สัดส่วน 0.95 ต่างจากช่องบนจอที่ใส่ 95 ให้ปิดแอปก่อนแก้ไฟล์แล้วเปิดใหม่ แอปที่เปิดค้างไม่โหลดไฟล์ใหม่อัตโนมัติ ช่องตั้งค่าบนจอเป็นวิธีที่สะดวกกว่า

threshold ต้องมากกว่า 0 และไม่เกิน 1 เวลาเป็นจำนวนบวกที่ไม่ใช่ NaN/Infinity ไม่มีล็อก 95% ทุกค่าต้องอยู่ในรูป JSON ถูกต้อง ถ้าใส่ค่าผิด โปรแกรมแสดงข้อผิดพลาด ไม่ฝืนใช้ค่าที่เสีย

## แยกจากเป้าหมายประเมินรุ่น

| ส่วน | ไฟล์ | ใช้เมื่อไร |
|---|---|---|
| คะแนนรับท่าและเวลา | live_settings.json | ตอนกล้องทำงาน ปรับผ่านช่องตั้งค่าได้ทันที |
| เป้าหมายคะแนนผ่าน validation | acceptance_policy.json | ตอนกด update_model_acceptance.cmd เพื่อตรวจและสลับรุ่น |
| รุ่นที่เปิดใช้งาน | latest_model.json | ตอนเปิดแอป |
| ค่าที่เคยประเมินพร้อมผลเดิม | models/.../selection_frozen.json | เก็บหลักฐานเดิม ไม่แก้ทับเพื่อปรับการเล่น |

acceptance_policy.json ที่คุณแก้เป็น 95% ยังอยู่ตามเดิม รุ่นนี้ชูโป้งขวา validation เดิม 89.9% จึงยังถูกปฏิเสธถ้ากด update_model_acceptance.cmd ด้วยเป้าหมาย 95% สิ่งนี้ไม่กีดกันการตั้ง threshold ขณะเล่นเป็น 95% ใน live_settings.json

รุ่นปัจจุบันเปิดไว้จากนโยบายประเมิน 85% แต่ขณะเล่นใช้คะแนนขั้นต่ำ 95% ตามที่ปรับใหม่ หน้าจอจึงแสดงสองตัวเลขนี้พร้อมกันได้ เป็นคนละความหมาย ผลการทดลองก่อนหน้าใช้ threshold 80% ไม่ยกผลนั้นมาอ้างว่า 95% ใหม่ผ่านการใช้งานจริงแล้ว

## วิธีลองและหาค่าที่เหมาะ

เริ่มด้วย 95%, ค้าง 0.6, ปล่อย 0.35 และช่องว่างภาพ 0.3 ตามที่ตั้งไว้ ลองกำมือ V ชูโป้ง และสามนิ้วทั้งสองมือ ดูว่าคำสั่งครบหรือไม่ ค้างแล้วส่งซ้ำไหม และปล่อยแล้วครั้งถัดไปติดไหม

ถ้าขึ้นยังไม่แน่ใจบ่อย ให้ลองจัดมือ/แสงก่อน แล้วปรับคะแนนลงครั้งละ 5 จุด เช่น 95→90 โดยคงเวลาอื่นเดิม ถ้าคะแนนผ่านแต่คำสั่งช้า ให้ดูความต่อเนื่องของท่าก่อนปรับเวลาค้าง ถ้าคำสั่งซ้ำหลังปล่อยชั่วครู่ ให้เพิ่มเวลาปล่อย ปรับทีละค่าเพื่อรู้ว่าค่าใดเป็นเหตุ

ไม่ต้องถ่ายข้อมูลฝึกเพิ่มสำหรับการปรับค่าเหล่านี้ ค่าที่ปรับไม่เปลี่ยนน้ำหนักโมเดล และทุกคำสั่งที่บันทึกต่อจากนี้มี runtime_settings แนบ เพื่อดูว่าทดสอบด้วยค่าอะไร
